# SURF2026 G1 语音交互 Pipeline 周报简版

周期：2026-07-02 至 2026-07-08  
分支：feature/jetson-robot-relay  
汇报重点：将同事版本中的 G1 真机语音、TTS、灯光、动作能力迁移到本机 WSL2 环境，并跑通完整链路。

## 1. 本周完成内容

### 1.1 完整真机 pipeline 跑通

本周已在 G1 真机上跑通完整流程：

    语音输入 / 唤醒词 -> ASR 识别 -> DeepSeek / LLM 回复 -> Edge TTS 生成语音 -> G1 机器人播放 -> 灯光反馈 -> 动作匹配与执行

目前已验证机器人可以完成语音问答、TTS 播放、灯光状态反馈，以及部分预设动作，例如挥手、打招呼等。

### 1.2 解决 WSL2 与 Unitree 音频接口冲突

最关键的问题是：本机 WSL2 直接初始化 Unitree AudioClient 时，会触发机器人端服务状态异常，影响音频和 ai_sport。

本周采用的解决方案是：

1. 在机器人 Jetson 端运行轻量 robot_relay 服务。
2. 本机 WSL2 不直接调用 Unitree AudioClient。
3. 本机通过 TCP 请求让机器人端 relay 代发 TTS、灯光、动作指令。

这个方案绕开了 WSL2 DDS / Unitree SDK 的兼容问题，也为后续测试提供了更稳定的架构。

### 1.3 接入 G1 语音播报、灯光和动作

已完成：

1. TTS wav 通过 relay 发给 G1 播放。
2. 唤醒、等待、回复等阶段可以触发灯光状态变化。
3. LLM 回复后可以根据关键词匹配预设动作。
4. 动作执行支持 relay 后端，避免本机直接连 Unitree SDK。

### 1.4 提升 TTS 和网络稳定性

测试中发现 TTS “时好时坏”其实来自多个环节：

1. DeepSeek HTTPS 请求偶发 SSL timeout。
2. Edge TTS WebSocket 偶发代理不生效。
3. LLM 请求失败后，后续不会进入 TTS，表现上像“没声音”。

已做改进：

1. Edge TTS 显式使用代理配置。
2. DeepSeek transient error 增加 retry。
3. 日志和 UI 中开始区分 LLM、TTS、播放、relay 等不同断点。

### 1.5 做了 G1 Pipeline Monitor UI

为了减少多终端调试的混乱，本周新增了一个简洁的浏览器监控页面：

1. 显示 pipeline 是否运行。
2. 显示语音识别、LLM 节点、TTS/动作播放器、机器人 relay 是否 ready。
3. 显示最新 ASR、最新回复、最近执行动作。
4. 显示每轮耗时：ASR、LLM、TTS、播放、动作、总计。
5. 显示实时事件流。
6. 支持从页面启动 / 停止 pipeline。

这个 UI 已经能用于日常真机测试和现场问题定位。

### 1.6 优化连续对话体验

已完成或初步完成：

1. 支持唤醒后连续多轮对话，不需要每一句都重新唤醒。
2. 放宽第一轮过滤逻辑，减少“唤醒后第一句话被忽略”。
3. 修复英文输入被 self-speech guard 过度拦截的问题。
4. 增加“再见 / 没有问题了 / bye bye”等结束意图，用于关闭当前 session。
5. 关闭效果不好的“思考动作 / 思考提示”，优先减少延迟和打断感。

### 1.7 调整小浦身份与回复风格

已把小浦定位为“西交利物浦大学校园智能语音机器人助手”。回复重点转向学校、校园服务、专业、申请、学费、宿舍、食堂、图书馆等问题。避免自称 Qwen / DeepSeek，也避免说自己只是虚拟助手。

### 1.8 增强唤醒词鲁棒性

当前唤醒词使用 sherpa-onnx KWS。已在 keywords.txt 中增加多种候选读法，例如：

1. 你好小浦
2. 连读 / 弱读版本
3. 嗨小浦
4. hi 小浦
5. hey 小浦

并新增了录音离线测试脚本。用户录制 5 段不同读法后，已有 3 段成功触发，说明方向可行。

## 2. 当前效果

目前已经达到阶段性目标：

1. 本机 WSL2 可以稳定接入 G1 真机。
2. 语音输入到 LLM 回复再到机器人播报的完整链路可跑通。
3. 机器人灯光和动作可以接入回复流程。
4. 有 UI 可以实时观察链路状态和耗时。
5. 已经有较清楚的日志和工作记录，方便继续迭代。

## 3. 当前主要问题

后续还需要继续优化：

1. DeepSeek / 外网 API 仍可能偶发超时，需要更好地显示错误来源，或考虑备用模型 / 备用回复。
2. ASR 有时会误识别学校名称，例如“西交利物浦大学”被识别成“新疆利物浦”等。
3. 连续对话窗口还需要继续调参：既要避免漏掉用户追问，也要避免环境噪声触发无意义回复。
4. 自动关闭 session 的策略还需要继续打磨，例如“再见”“我没有问题了”以及长时间无有效输入后的自然退出。
5. 当前播放耗时偏长，后续需要进一步分析 TTS 播放、relay 传输和 G1 播放之间的延迟来源。

## 4. 下周建议计划

建议按以下顺序继续：

1. 先修 LLM 超时显示和错误归因，让 UI 明确显示 DeepSeek timeout / TTS timeout / relay timeout。
2. 优化连续对话窗口和 session 自动关闭策略。
3. 增加学校关键词纠正，把“西浦 / XJTLU / 西郊利物浦 / 新疆利物浦”等统一理解为西交利物浦大学。
4. 继续补充唤醒词读法，提高不同语速、连读和中英文唤醒的成功率。
5. 在稳定基础上，再逐步优化动作触发、回复风格和展示效果。
